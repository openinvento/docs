# Updating & Backups

Keeping your OpenInvento installation up-to-date ensures you receive the latest features, security patches, and bug fixes. Because your database and media files are stored in a persistent volume, updating is straightforward and preserves all your data.

---

## Updating OpenInvento

When OpenInvento starts, it automatically applies any pending database migrations before launching the application server.

### With Docker Compose (Recommended)

1. Navigate to the directory containing your `docker-compose.yml`:
   ```bash
   cd /path/to/openinvento
   ```

2. Pull the latest image from GitHub Container Registry:
   ```bash
   docker compose pull
   ```

3. Restart the container in detached mode:
   ```bash
   docker compose up -d
   ```

4. Check container logs to verify successful database migrations:
   ```bash
   docker compose logs -f
   ```

---

### With Manual Docker Run

1. Stop and remove the existing container:
   ```bash
   docker stop openinvento
   docker rm openinvento
   ```
   *(Your data is preserved in the `openinvento-data` volume).*

2. Pull the newest image:
   ```bash
   docker pull ghcr.io/openinvento/openinvento:latest
   ```

3. Run the container again with **the same** volume and environment options as before, for example the `-e` options from the [installation](./docker#method-2-manual-docker-run). Keep the same `SECRET_KEY`. The example uses `--env-file .env`; if you installed with `-e` options and have no `.env`, put those same `-e` options in its place:
   ```bash
   docker run -d \
     --name openinvento \
     --restart unless-stopped \
     -v openinvento-data:/data \
     -p 8080:80 \
     --env-file .env \
     ghcr.io/openinvento/openinvento:latest
   ```

## Backing Up Your Data

OpenInvento provides multiple ways to back up your information, ranging from full system backups to inventory-specific CSV exports.

### 1. Instance Full Backup (One-Click)

Instance administrators can download a full archive containing the complete database and all uploaded files (photos and attachments) directly:

1. Log in with an administrator account.
2. Go to **Settings** &rarr; **Instance Settings**.
3. Click **Download Backup**.

Under the hood, this calls the `/api/instance-settings/backup/` endpoint, bundling the entire `DATA_DIRECTORY` into a compressed ZIP file named `openinvento-instance-backup.zip`.

:::caution Admin Privileges Required
The instance backup endpoint is restricted strictly to instance administrators because it archives the entire data store across all inventories.
:::

---

### 2. Manual Volume Backup (Host-Level)

You can also back up the Docker volume with a temporary helper container. Two things matter:

- **The volume name.** Docker Compose prefixes volumes with the project name, which is the name of the directory with `docker-compose.yml`. With the [installation guide](./docker), the volume is called `openinvento_openinvento-data`; with the manual `docker run` installation, it is `openinvento-data`. Check with `docker volume ls`. A wrong name silently creates a new, empty volume, and the backup contains nothing.
- **Stop OpenInvento first.** The database is a SQLite file. Copying it while OpenInvento writes to it can produce a broken copy.

With Docker Compose:

```bash
backup=openinvento-backup-$(date +%Y%m%d-%H%M%S).tar.gz
if docker compose stop; then
  docker run --rm \
    -v openinvento_openinvento-data:/volume-data \
    -v "$(pwd)":/backup \
    alpine tar -czvf "/backup/$backup" -C /volume-data . \
    || { rm -f "$backup"; echo "Backup failed, partial archive removed." >&2; }
  docker compose start
else
  echo "OpenInvento could not be stopped, no backup taken." >&2
fi
```

With the manual `docker run` installation:

```bash
backup=openinvento-backup-$(date +%Y%m%d-%H%M%S).tar.gz
if docker stop openinvento; then
  docker run --rm \
    -v openinvento-data:/volume-data \
    -v "$(pwd)":/backup \
    alpine tar -czvf "/backup/$backup" -C /volume-data . \
    || { rm -f "$backup"; echo "Backup failed, partial archive removed." >&2; }
  docker start openinvento
else
  echo "OpenInvento could not be stopped, no backup taken." >&2
fi
```

Nothing is archived if OpenInvento could not be stopped. If archiving fails, the partial archive is removed and the failure is reported; OpenInvento is started again either way. The time in the name keeps several backups of one day apart.

This creates a timestamped compressed `.tar.gz` archive of your entire data volume in your current directory.

:::caution Keep the SECRET_KEY with your backups
The archive contains the data directory, but not your `.env`. Third-party provider API keys are encrypted with the `SECRET_KEY` (see [Secret Key](../security/secret-key)). Store your `.env` (or at least the `SECRET_KEY`) securely next to the backups, and use the same key when you restore, otherwise these API keys cannot be decrypted.
:::

### 3. Inventory CSV Export

If you need a portable, human-readable export of a single inventory:

1. Open your inventory.
2. Navigate to **Inventory Settings**.
3. Click **Export Inventory**.

This generates a ZIP archive containing structured CSV files for your areas, shelves, boxes, categories, custom fields, and all articles.

## Restoring from a Backup

To restore data from a previous volume backup archive:

1. Stop OpenInvento:
   ```bash
   docker compose stop        # manual installation: docker stop openinvento
   ```

2. Restore the files into the data volume. The archive is checked first; only if it can be read completely are the current files deleted and replaced:
   ```bash
   docker run --rm \
     -v openinvento_openinvento-data:/volume-data \
     -v "$(pwd)":/backup \
     alpine sh -c "tar -tzf /backup/openinvento-backup-YYYYMMDD-HHMMSS.tar.gz > /dev/null && find /volume-data -mindepth 1 -delete && tar -xzvf /backup/openinvento-backup-YYYYMMDD-HHMMSS.tar.gz -C /volume-data"
   ```
   Use the same volume name as for the backup (`openinvento-data` for the manual `docker run` installation).

3. Start OpenInvento again:
   ```bash
   docker compose start       # manual installation: docker start openinvento
   ```
